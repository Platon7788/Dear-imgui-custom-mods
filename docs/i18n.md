# Localisation (i18n) — English / Russian

Every widget in this crate that renders user-visible text supports
runtime locale switching through `crate::i18n`. The default is
English; hosts opt into Russian per widget.

Established across session 042; nine standalone widgets currently
ship full bilingual catalogues. Any new widget with user-visible
strings **must** integrate the same way.

## Quick start (host-side)

```rust
use dear_imgui_custom_mod::i18n::Locale;

let viewer    = HexViewer::new("##h").with_locale(Locale::Ru);
let disasm    = DisasmView::new("##d").with_locale(Locale::Ru);
let editor    = CodeEditor::new("##e").with_locale(Locale::Ru);
let fm        = FileManager::new().with_locale(Locale::Ru);
let tabs      = TabControl::<MyTab>::new("##t").with_locale(Locale::Ru);
let graph     = GraphViewer::new("##g").with_locale(Locale::Ru);
let timeline  = Timeline::new("##tl").with_locale(Locale::Ru);
let diff      = DiffViewer::new("##df").with_locale(Locale::Ru);

// nav_panel — functional API, set the field directly:
let mut nav_cfg = NavPanelConfig { locale: Locale::Ru, ..Default::default() };
```

`Locale` is `serde::Serialize + Deserialize`, and every widget's
config carries `locale: Locale` as a `#[serde(default)]` field, so
the choice round-trips through `ron::to_string` / `ron::from_str`
along with every other display setting.

## Font atlas requirement

Russian renders Cyrillic characters; the host must bake
`crate::app_window::GlyphRanges::Cyrillic` (or a superset) into the
active ImGui font atlas before switching to `Locale::Ru`. Without
that, non-ASCII characters render as `?` placeholders.

This is documented on the `Locale::Ru` variant itself — the
font-atlas wiring is host-controlled, the crate cannot enforce it.

## Adding a new widget with user-visible strings

The pattern below mirrors what the nine existing widgets do. Use any
of them as a template — `i18n::file_manager` has the most fields,
`i18n::nav_panel` the fewest.

### 1. Add a sub-module to `crate::i18n`

```rust
// src/i18n.rs
pub mod my_widget {
    #![allow(missing_docs)]      // field names are self-describing

    use super::Locale;

    #[derive(Debug)]
    pub struct Strings {
        pub menu_open: &'static str,
        pub menu_save: &'static str,
        pub status_ready: &'static str,
        // ...
    }

    pub const EN: Strings = Strings {
        menu_open: "Open",
        menu_save: "Save",
        status_ready: "Ready",
    };

    pub const RU: Strings = Strings {
        menu_open: "Открыть",
        menu_save: "Сохранить",
        status_ready: "Готово",
    };

    pub fn strings(locale: Locale) -> &'static Strings {
        match locale {
            Locale::En => &EN,
            Locale::Ru => &RU,
        }
    }
}
```

### 2. Format-template strings get standalone helpers

```rust
pub fn result_n_of_m(locale: Locale, idx: usize, total: usize) -> String {
    match locale {
        Locale::En => format!("Result {idx}/{total}"),
        Locale::Ru => format!("Результат {idx}/{total}"),
    }
}
```

Use these for any string that takes a runtime parameter — pluralisation
rules and word order differ across languages, so a static template
field with `{}` placeholders won't work.

### 3. Add `locale: Locale` to the widget's config

```rust
// src/my_widget/config.rs
#[derive(serde::Serialize, serde::Deserialize)]
pub struct MyWidgetConfig {
    // ... other fields ...

    /// User-visible language. Default `Locale::En`.
    /// Switching to `Locale::Ru` requires `GlyphRanges::Cyrillic` in
    /// the active font atlas.
    #[serde(default)]
    pub locale: crate::i18n::Locale,
}
```

`#[serde(default)]` so older saved ron files (pre-locale field) still
parse cleanly, falling back to `Locale::En`.

### 4. Add `locale: En` to `config.ron`

```ron
(
    // ... existing fields ...
    locale: En,
)
```

### 5. Wire builder + accessors on the widget

```rust
impl MyWidget {
    #[must_use]
    pub fn with_locale(mut self, locale: crate::i18n::Locale) -> Self {
        self.config.locale = locale;
        self
    }

    pub fn set_locale(&mut self, locale: crate::i18n::Locale) {
        self.config.locale = locale;
    }

    pub fn locale(&self) -> crate::i18n::Locale {
        self.config.locale
    }

    fn strings(&self) -> &'static crate::i18n::my_widget::Strings {
        crate::i18n::my_widget::strings(self.config.locale)
    }
}
```

If your widget owns a mirror catalogue field on its config (like
`FileManager::config.strings: &'static FmStrings`), `set_locale` /
`with_locale` must auto-refresh it — see
`FileManager::set_locale` for the reference impl.

### 6. Use the catalogue in render code

```rust
fn render_menu(&mut self, ui: &Ui) {
    let s = self.strings();
    if ui.menu_item(s.menu_open) { /* ... */ }
    if ui.menu_item(s.menu_save) { /* ... */ }
}
```

### 7. Add the four guard tests

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use crate::i18n::Locale;

    #[test]
    fn strings_en_and_ru_diverge() {
        assert_ne!(crate::i18n::my_widget::EN.menu_open,
                   crate::i18n::my_widget::RU.menu_open);
    }

    #[test]
    fn config_default_locale_is_english() {
        assert_eq!(MyWidgetConfig::default().locale, Locale::En);
    }

    #[test]
    fn config_locale_round_trips_through_ron() {
        let cfg = MyWidgetConfig { locale: Locale::Ru, ..Default::default() };
        let text = ron::ser::to_string(&cfg).unwrap();
        let back: MyWidgetConfig = ron::from_str(&text).unwrap();
        assert_eq!(back.locale, Locale::Ru);
    }

    #[test]
    fn config_locale_field_optional_in_ron() {
        // Pre-locale ron files must still parse — `#[serde(default)]` guard.
        let cfg: MyWidgetConfig = ron::from_str(/* ron without `locale:` */).unwrap();
        assert_eq!(cfg.locale, Locale::En);
    }
}
```

## What stays untranslated

These are deliberate exceptions, not laziness:

| Category | Examples | Why |
|---|---|---|
| Programming-language IDs | Rust, RON, JSON, TOML, YAML | Proper nouns |
| Theme display names | DarkDefault, Dracula, Github | Proper nouns |
| Keyboard shortcuts | Ctrl+X, F3, Esc | Cross-locale technical |
| RE/debug abbreviations | Hex, Dec, Oct, Bin, ASCII, UTF-8, UTF-16LE | Conventional in Russian RE/debug context too |
| Host-supplied labels | `NavItem::label`, `Track::name`, `Span::label` | Host owns the user's mental model |
| Widgets without strings | `node_graph` (pure draw) | No labels to translate |

## Locale on host-driven widgets

Host-driven widgets — `confirm_dialog`, `notifications`,
`property_inspector`, `status_bar`, `toolbar`, `virtual_table`,
`virtual_tree` — accept their entire labelled UI from the host
(e.g. `status_bar.add_left_item("Файл")`). They do not carry a
`Locale` field because the host has already chosen the language by
the time it constructs the labels. This is by design.
